# Multi-Agent Workflows

So far you've built a single agent that can use tools. That's already powerful — but what happens when a task is too big, too complex, or just more naturally split into parts?

That's where **multi-agent workflows** come in. Instead of one agent doing everything, you build a *team* of agents, each with a clear job, and let ADK coordinate them.

Think of it like a kitchen: you don't want one person chopping, cooking, plating, and serving at the same time. You split the work.

---

## The building blocks

ADK gives you three special agents whose only job is to *coordinate* other agents:

| Agent | What it does |
|---|---|
| `SequentialAgent` | Runs agents one after another, in order |
| `ParallelAgent` | Runs agents at the same time |
| `LoopAgent` | Keeps running agents in a loop until a condition is met |

You nest your regular `LlmAgent`s inside these as `sub_agents`.

---

## 1. SequentialAgent — one step at a time

Use this when each step needs the result of the previous one. Like an assembly line: you can't paint the car before the frame is built.

```python
from google.adk.agents import SequentialAgent, LlmAgent

# Step 1: Research a topic, save the result to state['research']
researcher = LlmAgent(
    name="Researcher",
    model="gemini-2.0-flash",
    instruction="Research the topic the user gave you. Be thorough.",
    output_key="research",  # saves the response to shared state
)

# Step 2: Turn that research into a short summary
summariser = LlmAgent(
    name="Summariser",
    model="gemini-2.0-flash",
    instruction="Write a short, friendly summary of: {research}",
)

pipeline = SequentialAgent(
    name="ResearchPipeline",
    sub_agents=[researcher, summariser],  # order matters!
)
```

The key trick here is `output_key`. When `researcher` finishes, its response is stored as `state['research']`. Then `summariser` can reference it in its instruction using `{research}`.

---

## 2. ParallelAgent — do it all at once

Use this when your tasks are independent of each other and you want speed. Instead of waiting for one to finish before starting the next, they all run at the same time.

```python
from google.adk.agents import ParallelAgent, LlmAgent

fetch_weather = LlmAgent(
    name="WeatherFetcher",
    model="gemini-2.0-flash",
    instruction="Get the current weather for London.",
    output_key="weather",
)

fetch_news = LlmAgent(
    name="NewsFetcher",
    model="gemini-2.0-flash",
    instruction="Get today's top news headlines.",
    output_key="news",
)

gatherer = ParallelAgent(
    name="InfoGatherer",
    sub_agents=[fetch_weather, fetch_news],
)
```

Both agents run concurrently and each saves its output to shared state (`state['weather']` and `state['news']`). A follow-up agent could then read both and combine them into a morning briefing.

> **Tip:** `ParallelAgent` is great for fan-out / gather patterns — fan out to many agents, then gather their results in a single synthesis step.

---

## 3. LoopAgent — keep going until done

Use this when you don't know upfront how many steps are needed. The loop keeps running until either `max_iterations` is reached or one of your agents signals it's done by setting `escalate=True`.

```python
from google.adk.agents import LoopAgent, LlmAgent, BaseAgent
from google.adk.events import Event, EventActions
from google.adk.agents.invocation_context import InvocationContext
from typing import AsyncGenerator

# A simple checker that reads from state and stops the loop when ready
class DoneChecker(BaseAgent):
    async def _run_async_impl(self, ctx: InvocationContext) -> AsyncGenerator[Event, None]:
        status = ctx.session.state.get("status", "pending")
        is_done = (status == "completed")
        yield Event(author=self.name, actions=EventActions(escalate=is_done))

refiner = LlmAgent(
    name="Refiner",
    model="gemini-2.0-flash",
    instruction="Improve the draft in state['draft']. Save the new version back.",
    output_key="draft",
)

loop = LoopAgent(
    name="RefinementLoop",
    max_iterations=5,
    sub_agents=[refiner, DoneChecker(name="Checker")],
)
```

A common use case: a *generator-critic* pattern where one agent writes content and another reviews it, looping until the critic is happy.

## 4. Coordinator pattern — let an LLM decide who does what

Sometimes you don't want a fixed workflow. You want an intelligent dispatcher that reads the user's request and decides which specialist to hand it off to.

For this, you use a regular `LlmAgent` with `sub_agents`. The LLM figures out who to call based on the sub-agents' descriptions.

```python
from google.adk.agents import LlmAgent

billing_agent = LlmAgent(
    name="BillingAgent",
    model="gemini-2.0-flash",
    description="Handles questions about invoices, payments, and subscriptions.",
    instruction="You are a billing specialist. Help the user with their billing query.",
)

technical_agent = LlmAgent(
    name="TechnicalAgent",
    model="gemini-2.0-flash",
    description="Handles technical issues, bugs, and how-to questions.",
    instruction="You are a technical support specialist. Help the user solve their problem.",
)

coordinator = LlmAgent(
    name="SupportCoordinator",
    model="gemini-2.0-flash",
    instruction="""You are a customer support coordinator.
Read the user's message carefully, then hand it off to the right specialist.
Do not answer directly — always delegate.""",
    sub_agents=[billing_agent, technical_agent],
)

root_agent = coordinator
```

The `coordinator` reads the incoming message and calls `transfer_to_agent("BillingAgent")` or `transfer_to_agent("TechnicalAgent")` automatically. You don't wire this up manually — the LLM handles it based on the descriptions you write.

> **Tip:** Write clear, specific `description` fields on your sub-agents. That's what the coordinator reads to decide who gets the task.

## Putting it together

These patterns compose. A coordinator can hand off to a sequential pipeline. A parallel fan-out can feed into a loop. You build workflows like Lego bricks.

Here's a mental model for picking the right one:

- **Need results in order?** → `SequentialAgent`
- **Tasks are independent and slow?** → `ParallelAgent`
- **Don't know when to stop?** → `LoopAgent`
- **Need smart routing?** → `LlmAgent` with `sub_agents`
